# WNM-PGB1-firmware (multivoice/soundmodule fork)

The PGB-1 is a pocket-sized open-source groovebox: eight tracks, six of them
synth engines and two samplers, with a deep sequencer, chord and song modes,
onboard sampling and effects, all running on an RP2040. It is made by
[Wee Noise Makers](https://weenoisemakers.com) (Fabien Chouteau) and sold
through [Crowd Supply](https://www.crowdsupply.com/wee-noise-makers/wee-noise-makers-pgb-1)
and the usual synth retailers.

Upstream firmware lives at
[wee-noise-makers/WNM-PGB1-firmware](https://github.com/wee-noise-makers/WNM-PGB1-firmware).
This fork's changes are by Joseph Wozniak ([woz.lol](https://woz.lol)).

**Building.** One fix lives in a pinned dependency, which Alire keeps in the
gitignored `device/alire/cache/`. Build once so Alire fetches the pins, run
`./patches/apply.sh`, then build again. Always build `--release`, debug builds
do not run correctly on the hardware.

## What's changed

**Audio**

- **The periodic output click is gone.** Stock firmware clicks a couple of
  times a second on headphones, on every instrument, at any volume. The codec
  now takes its sample clock from the incoming bit clock rather than its own
  reference, so the two can no longer drift apart. Applied by
  `patches/apply.sh`.
- **Headphone-detect poll runs once a second instead of four times a second.**
  Each poll is an I2C transaction that put a faint tick in the output.
- **Waveforms are band-limited per pitch zone**, read on a 1024-point grid,
  generated by `scripts/gen_chord_wavetables.py` into `common/generated/`.
  Removes the inharmonic fizz that the bright waveforms produced up high:
  Sawtooth, both Pulses, Screech and Sine+Saw. Costs flash only, no RAM and no
  extra work per sample.

**Chord track**

- **Polyphonic, 1 to 5 voices, settable.** Each voice has its own envelope, so
  releasing one note out of a held chord fades only that note, click-free.
- **Voice stealing with note memory.** Play past the voice count and the oldest
  note gives way immediately. If you are still holding that key, it comes back
  as soon as a voice frees up, the way a real poly synth allocates.
- **Voice count no longer changes the level.** The mix-down uses a fixed
  divisor, so going from 1 voice to 5 does not make every note quieter.

**Interface**

- **Last Note Retrigger, per track, with its own tab.** Hold a note, tap
  another, release the newer one, and the voice returns to the key you are
  still holding instead of cutting out. On every synth track except Chord,
  which has real polyphony instead. Previously this was attached to the Arp
  mode tab, which had nothing to do with it.
- **Settings tabs wrap around** at both ends instead of stopping.
- **The Chord params screen names the current waveform** instead of just saying
  "Waveform".
- **Lead's Buzz first param is labeled "Comb Brightness"**, which is what it
  does. It slides across band-limited comb tables and never selected a named
  waveform.
- **The "Arpeggiator notes" tab is hidden.** Its setting has exactly one
  possible value, so the tab had nothing to cycle to. Commented out rather than
  deleted, in `Valid_Setting`.

## Known limitations

- Chord is capped at 5 voices. Each voice carries its own envelope for
  click-free release, and 5 is what fits in RAM alongside everything else.
- Bass and Lead are still monophonic. Their "number of voices" setting does
  nothing.
- Chord's Glide knob does nothing. An earlier implementation caused artifacts
  and was removed rather than shipped broken.
- The Chord Mode setting, Generated or Direct Poly, only affects sequenced
  steps whose Note Mode is "Chord" or "Note in Chord". It has no effect on live
  playing in either mode, which matches stock behavior for the harmonized
  chord-progression feature.
- The custom user waveform is drawn at run time, so there is no precomputed
  band-limited copy of it and it reads the coarse table as before.
- The codec's line input is summed into the output on every buffer whether or
  not anything is plugged in, so its noise floor is always present. Skipping it
  outright would break live input monitoring, so doing it properly means gating
  on whether monitoring is wanted.
- Headphone detection is still polled. The IO expander has an interrupt line,
  and driving detection from it would remove the remaining tick entirely.

## How the click was found

Worth writing down, because the symptom pointed away from the cause the whole
way.

The RP2040's PIO generates the I2S clocks by dividing the system clock, and the
divider is 16.8 fixed point, so at 133 MHz the closest it gets to 32 kHz is
32,001.925 Hz. The codec was generating its own sample clock from its 24 MHz
reference and landing on 31,999.80 Hz. Those differ by about two hertz, so the
codec slipped roughly twice a second, and every slip was a click. The samples
were always correct, which is why nothing done to the audio code helped.

Ruled out by measurement rather than guesswork:

- A bit-exact 500 Hz tone written straight into the output, bypassing every
  instrument and mix stage, still clicked. So not the DSP.
- The PIO's sticky `TXSTALL` flag never set, so the output never starved, and
  the mixer's dropped-buffer counter never moved, so the queue never ran dry.
- A per-sample discontinuity detector watching the finished mix found nothing
  across ten seconds of a held note while the clicks were plainly audible.
- Reading the PIO's clock divider register gave the exact rate error, and its
  arithmetic predicted the click rate actually being heard. Moving the system
  clock to 200 MHz, where the divider is exactly representable, changed the
  click rate as predicted, which confirmed the mechanism before the real fix.

The fix sources the codec's PLL from the bit clock, so its rate is defined by
ours at any system clock. For 32 kHz that is J=32, D=0, R=2, P=1, exactly.

Dead ends along the way, for the record: aliasing, the DMA buffer handoff, and
wavetable interpolation. All measured, all innocent.

## Earlier milestone: Chord polyphony and note-priority retrig (2026-09-28)

The Chord engine originally summed all four of its voices unconditionally, so a
released note never actually stopped and live playing produced a drone. That,
the per-voice envelopes, the click-free voice stealing and the note-priority
retrig sidecar all landed here. See the list above for the end state.
